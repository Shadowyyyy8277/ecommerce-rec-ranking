# 作品集项目说明：端到端电商多路召回与 CTR 排序系统 (Ecommerce Rec-Ranking)

## 一、项目定位

本项目面向“推荐算法工程师 / 机器学习工程师”全职与实习岗位，完整复现了工业界推荐系统的核心技术链路与工程闭环：
`数据仿真与质量校验 → 防穿越特征工程 → 多路召回融合与去重 → 多模型 CTR 排序对比 → 全指标离线评估 → 统一模型注册表 → FastAPI 高并发在线推理 → Docker/CI/CD 容器化工程部署`。

---

## 二、核心业务问题与系统设计

电商场景下海量商品（$10^6 \sim 10^8$）与用户实时请求（$<50\text{ms}$）之间存在吞吐与算力的天然矛盾。本项目采用分层漏斗架构：
1. **召回层（Recall）**：通过规则召回（Popular）、协同过滤（ItemCF）、表示学习（Item2Vec）三路策略，兼顾热门曝光、行为关联与语义相似，将候选集压缩至百级；
2. **排序层（Ranking）**：提取用户画像、商品属性、交叉统计与上下文动态特征，对比 LR、LightGBM、DeepFM 等模型精准预测 CTR 概率；
3. **服务层（Serving）**：FastAPI 提供低延迟推理，支持模型注册表动态热加载与冷启动/缺失模型平滑降级（Fallback）。

---

## 三、关键技术亮点（简历加分项）

1. **严格时间切分与特征防穿越（Data Leakage Prevention）**：
   - 按时间序列切分 $Train < Valid < Test$，防止未来信息穿越；
   - 训练集历史统计特征采用累积窗口（Cumulative History），当前样本不读取自身 label；
   - 验证集与测试集统计特征严格仅拟合训练集数据。
2. **多路召回融合与自适应去重**：
   - 结合 Popular（业务权重加权）、ItemCF（时间衰减与惩罚热门）、Item2Vec（PyTorch Skip-Gram 负采样嵌入）；
   - 候选集合并时按最高置信度自适应去重，并剔除用户历史正向交互行为。
3. **可扩展模型注册表模式（Model Registry Pattern）**：
   - 统一抽象模型的训练与推理分发协议，新增模型无需改动评估与服务代码，达到生产级代码解耦。
4. **全方位离线评估体系**：
   - CTR 预测分类指标：AUC、LogLoss；
   - Top-K 推荐排序指标：Precision@K、Recall@K、NDCG@K、HitRate@K、MRR@K（平均倒数排名）；
   - 系统性能基准：P99 单样本推理延迟（$<0.05\text{ms}$）、模型存储尺寸。
5. **现代生产级 MLOps 与工程规范**：
   - 现代化 Python 打包规范（`pyproject.toml`，支持 `pip install -e .` 与 CLI 命令）；
   - Docker 容器化与 Docker Compose 一键编排（API + Streamlit Dashboard + MLflow）；
   - GitHub Actions 自动化 CI 流水线（Matrix 测试多 Python 版本 + Ruff 静态分析）；
   - 21 个自动化测试用例，覆盖 API 校验、特征编码器、各路召回、排序模型和评估指标。

## 五、高频面试问题深度解析（Q&A 准备）

1. **Q：为什么用户行为类型（behavior_type）不能直接作为 CTR 排序模型的输入特征？**
   - **A**：因为 `behavior_type`（浏览/加购/收藏/购买）正是生成排序目标（Label）的来源！如果作为输入特征，会在训练时直接泄露目标标签（Label Leakage），导致模型学到平凡恒等映射（购买必然点击），在测试和实际在线推理场景中线上请求根本没有未来的 behavior 信息，模型预测直接失效。

2. **Q：ItemCF 与 Item2Vec 的核心差异与互补性是什么？**
   - **A**：ItemCF 依赖协同过滤中的显式共现频率矩阵与余弦相似度，对高频紧密共现商品召回准确度极高，但在稀疏长尾场景下表现乏力；Item2Vec 借鉴 Word2Vec 词向量思想，将用户行为序列视为句子、商品视为词，在低维连续向量空间学习全局上下文语义关联，能够有效挖掘语义相近但物理共现频次低的长尾候选，二者融合能兼顾精确度与泛化多样性。

3. **Q：DeepFM 模型架构相对于传统 FM 和 Wide&Deep 有何优势？**
   - **A**：Wide&Deep 需要人工设计特征交叉组合（Cross-product transformations）作为 Wide 部分；而 DeepFM 共享相同的 Embedding 输入，FM 部分自动建模一阶特征和二阶特征交叉，DNN 部分建模高阶非线性特征交互，免去了繁重的人工特征组合工程，且端到端联合训练。

4. **Q：系统如何保障生产环境的鲁棒性与高可用？**
   - **A**：
     - ① **容灾降级（Fallback）**：当模型加载失败或实时推理异常时，自动平滑降级至热门候选商品兜底，保证接口恒定返回 200；
     - ② **防御式 MLflow**：MLflow 仅用于实验追踪，其连接失败不会阻断核心训练与模型本地持久化；
     - ③ **请求防御与缓存**：FastAPI 配置严格的 Pydantic 数据校验与范围约束（$1 \le K \le 100$），配置信息与离线基准特征采用 LRU 缓存并做深浅拷贝保护。
